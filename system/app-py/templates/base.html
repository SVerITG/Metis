{#- `hx-disinherit="*"` on every nav item is load-bearing, not decoration. htmx resolves hx-target, hx-select and hx-push-url by walking UP the DOM (`getClosestAttributeValue`). So any child element inside a nav item that makes its own request inherits that item's whole navigation contract. The Learning item has exactly such a child — the `n-meta` badge, which polls `/api/partial/learning/nav-meta` on load and every 300s. Without disinherit that tiny "4 courses" fragment ran with hx-target="#tab-content", hx-select="#tab-content" (which the fragment does not contain, so the swap emptied the surface) and hx-push-url="/learning" — silently rewriting the address bar to /learning seconds after every page load, and again every five minutes. Reload, or open the dashboard from the shortcut, and you landed on Learning no matter which surface you had chosen. Bug found 2026-08-26; it was the only nav item with a self-fetching child, which is why the dashboard always drifted to Learning specifically. `hx-swap="outerHTML"` (not innerHTML) pairs with hx-select="#tab-content": hx-select hands htmx the matched ELEMENT, so an innerHTML swap nested a second #tab-content inside the first on every nav click — duplicate IDs and a fresh 28/32/64px of padding each time. -#}
